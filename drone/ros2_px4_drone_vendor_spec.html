01

文件目的與使用方式

本文件在採購流程中同時扮演三種角色，並以同一份內容對外溝通，避免規格在郵件與會議紀錄之間產生分歧。

  1. 採購規格單：第 2 節的硬體規格需求單為報價與下單的規格基礎，供應商投標內容不得低於表列最低需求。
  2. 介面凍結依據：第 3 節的韌體、訊息套件、Topic 與參數集為雙方共同凍結的介面，任何一方皆不得單方面變更。
  3. 交付驗收的執行清單：第 5 節的台架驗收清單為交付後逐項執行的驗收程序，其結果決定該批次是否完成驗收。

角色邊界

下表界定機體交付範圍內的責任歸屬。表中未列出的項目，默認由本團隊負責。

範圍 供應商負責 本團隊負責
機體與動力 機架、馬達、ESC、電源模組組裝與出廠測試 驗收與試飛
飛控韌體 依指定版本燒錄、出廠參數集載入 參數集內容定義、後續調參
感測器 依清單安裝、接線、驅動啟用 讀值驗證、校正與融合
ROS 2 自主堆疊 不提供 全部（VIO、AprilTag、規劃、避障）
通訊 uXRCE-DDS client 啟用、MAVLink 遙測 Micro XRCE-DDS Agent、QGC

責任分界原則

供應商對「硬體能開機、能通電、能依規格輸出訊號」負責；本團隊對「資料正確性、融合行為、飛行安全與自主邏輯」負責。出廠測試報告屬於入場文件，最終驗收結論以第 5 節的執行結果為準。

03

軟體與韌體介面契約

本節為雙方凍結的介面清單。凍結後任何變更皆進入第 6 節的變更管理程序。uXRCE-DDS Agent 由本團隊於伴飛電腦運行，供應商僅需確保飛控端 client 已啟用並可連線。

介面凍結清單

  1. PX4 韌體 commit SHA：由雙方於第一批交付前確認並記錄於本文件附件。
  2. px4_msgs 套件版本：與韌體 commit 對應，確保訊息定義一致。
  3. airframe 參數集檔案：供應商依本團隊提供的 .params 檔載入，不得自行調整內容。
  4. uXRCE-DDS transport：實機優先使用 UART 或專用 Ethernet；SITL 或核准的專用 UDP 網路可使用 Agent port 8888。UXRCE_DDS_CFG、UXRCE_DDS_PTCFG 等參數以凍結參數檔為準，不得將 UXRCE_DDS_PTCFG 等同 UDP port。
  5. MAVLink 遙測：QGC 以 UDP 14550 連線。

Topic 契約表

本表沿用架構藍圖的 topic 速查表，為 DDS 橋接的驗收項目。頻率量測以 ros2 topic hz 為準。

方向 Topic 用途 驗收要求
飛控 → ROS 2 /fmu/out/vehicle_odometry 狀態回傳 發布頻率不低於 50 Hz
飛控 → ROS 2 /fmu/out/vehicle_local_position 位置狀態 發布頻率不低於 50 Hz

ROS 2 → 飛控 /fmu/in/vehicle_visual_odometry 視覺里程計 飛控 EKF2_EV_CTRL 融合路徑暢通

下列參數由供應商於出廠時燒入，內容由本團隊提供 .params 檔。參數值以檔案內容為準，表中僅列設定目的。

參數 設定目的

凍結的意義

介面凍結後，供應商不得以「最新版較穩定」為由更換韌體或訊息套件。任何版本替換皆視為介面變更，須完成第 6 節程序並重新執行第 5 節的 B 組與 D 組驗收。

04

分批交付計畫

交付分兩批進行。第一批為台架用的 dev kit，讓本團隊在整機到位前即可展開介面驗證與 EKF2 融合測試；第二批為完整可飛機體。

批次 交付時點 內容 附件要求
第一批（dev kit） W2 前 飛控本體＋測距儀＋GPS＋接收機＋電源模組（台架用） 韌體版本證明、參數集載入證明
第二批（整機） W11 前 完整可飛機體 ×2：機架、動力、伴飛電腦、相機、LiDAR、全部接線與安裝（第 2 組可降級為完整備件包，由採購方於議價前核定） 出廠測試報告（項目須涵蓋第 5 節 A–D 全部勾選項）、線序圖、電氣規格表、推力台架數據（對應第 2 節動力性能規格表之量測項）、實機秤重證明

供應商延遲不影響本團隊 SITL 開發排程（詳見團隊執行規劃的降級方案），但第二批延遲將觸發第 6 節的變更管理程序。

05

台架驗收清單（Checklist）

以下清單由本團隊於交付後 3 個工作日內執行；分 A–G 七組，每項含驗收方法與合格標準。任一「必要」項不通過即驗收失敗，該批次退回並進入第 6 節的修復程序。動力相關項目（F 組）以第 2 節「動力性能規格」表為判定基準。

組別 項目 驗收方法 合格標準 必要性
A 開機與電氣 A1 通電次序與開機 依供應商電氣規格表通電 飛控與伴飛電腦皆正常開機 必要
A2 伴飛電腦供電軌 帶滿載（相機與 LiDAR 運轉）量測獨立 DC-DC 穩壓器輸出電壓軌 電壓在 Jetson 載板輸入規格容差內、紋波與壓降符合規格 必要
B 飛控與韌體 B1 韌體版本核對 QGC 關於頁面比對凍結的 commit SHA 完全一致 必要
B2 參數集核對 QGC 匯出參數與 .params 契約檔 diff 僅僅允許附件白名單所列 calibration／device ID 參數不同；飛行模式、failsafe、EKF、DDS、airframe、actuator 與 battery 參數必須一致且皆為校正類 必要
B3 QGC 連線 UDP 14550 與 serial 遙測各連一次 均可連線且延遲低於 500ms 必要
B4 RC 綁定與接管 模擬失聯 觸發設定之 failsafe（RTL 或 Hold） 必要
C 感測器 C1 測距儀 uorb top 觀察 distance_sensor 頻率不低於 30Hz、讀值隨高度變化正確 必要
C2 雙目相機 rosbag 錄 10 秒左右目影像與 IMU 影像 30fps 左右、無掉幀超過 1%、IMU 時間戳與影像同步 必要
C3 LiDAR（選配） 點雲話題開啟 點雲完整、無大面積遮擋 選配
D DDS 橋接 D1 Agent 連線 伴飛電腦運行 MicroXRCEAgent udp4 -p 8888 client 連上、無斷線重連 必要
D2 topic 頻率對表 ros2 topic hz 逐項量測第 3 節 Topic 契約表 全部達標 必要
D3 offboard 閉環 發送 offboard_control_mode + trajectory_setpoint 飛控進入 offboard 且姿態響應正確（繫留或台架） 必要
E EKF2 融合 E1 測距儀融合 開 EKF2_RNG_CTRL 懸停邏輯（台架） EKF 狀態綠、無創新量發散 必要
E2 視覺融合 灌入 VIO 里程計（台架搖動機體） EKF2_EV 融合追蹤、無 yaw 發散 必要
F 動力與安全 F0 動力性能核對 出廠推力台架數據對照第 2 節動力性能規格表逐項核對 全部量測項達標 必要
F1 ESC 校正與馬達序 依 airframe 測試 四馬達順序與轉向正確 必要
F2 電池 failsafe 低電壓模擬 觸發設定之 failsafe 必要
G 機構 G1 振動 怠速與半油門（繫留）錄 IMU 振動頻譜在飛控容許範圍 必要
G2 視野 相機畫面確認 無槳葉入鏡、無結構遮擋 AprilTag 偵測視野 必要

「必要」項任一不通過即整批驗收失敗；「選配」項依實際採購配置決定是否執行，未配置 LiDAR 時 C3 標記為不適用（N/A），不影響驗收結論。

驗收紀錄

每項驗收須留下可追蹤證據：終端機輸出、rosbag 檔名、QGC 截圖或量測數據。證據與清單編號一併歸檔，作為第 6 節爭議處理的依據。

06

變更與爭議管理

本節定義介面變更、驗收失敗與交付延遲的處理規則，雙方於簽署本文件時一併同意。

  1. 介面凍結項變更：第 3 節任一凍結項的變更須經雙方書面同意，並更新本文件版本號；未經同意即變更者視為交付不符。
  2. 驗收失敗：驗收失敗項由供應商於 5 個工作日內修復並安排重驗；重驗仍以第 5 節同一清單執行。
  3. 第二批延遲：第二批延遲每滿 1 週，交付驗收時程與里程碑（M4、M5）同步順延，並由雙方簽認順延紀錄。
  4. 第一批獨立性：第一批（dev kit）不受第二批延遲影響，其交付與驗收時點維持不變。

文件版本控制

本文件與 git repo 同步維護，任何修訂以 repo commit 為準。文件版本號於每次經雙方同意的修訂後遞增，並在 commit 訊息中標明變更章節。
