AMCL vs slam_toolbox Localization

同一台車、同一張 5.25 × 17.3 m 走廊地圖的實測比較

ROS 2 Jazzy · RPLIDAR S2 · rf2o + EKF · 2026-11-05

1. 結論先講

AMCL 不適合這條長走廊

粒子濾波在對稱走廊會出現多峰翻轉：實測 28 次 > 0.3 m 的 map→odom 跳變，最大 3.33 m / 0.43 rad，每秒在 x = +0.5 / −1.3 / +2.2 之間跳。

slam_toolbox localization 建議使用

用 posegraph + 掃描匹配 定位，有「上次經過這裡的完整掃描」當 prior，走廊段沒有觀察到 AMCL 那種 2~3 m 的多峰翻轉；啟動與定位測試正常。

注意：slam_toolbox localization 需要先前的 .posegraph + .data。 只有 pgm + yaml 時只能用 AMCL。

2. 兩種定位的資料流

AMCL

pgm + yaml（靜態佔據圖） │ /scan ──┼──► 粒子濾波（2000 particles） │ │ odom ───┘ ▼ map → odom（10 Hz 更新） │ ▼ map → base_link
  • 只拿到「這一格是不是牆」
  • 沒有 map 更新、沒有迴環
  • 對稱環境 → 多峰 → 跳變

slam_toolbox localization

.posegraph + .data（含每個節點的原始掃描） │ /scan ──┼──► Karto scan matching（對既有圖） │ │ odom ───┘ ▼ map → odom（10 Hz 更新） │ ▼ map → base_link
  • 比對「整段掃描特徵」而非單一格子
  • 不新增節點、不建圖
  • 走廊比 AMCL 穩定

6. 操作指令

6.1 建圖（mapping，先存圖 + posegraph）

# 建圖（loop closure 開啟）
cd /nvt_ros2_example/slam_toolbox_rf2o
./start_slam_toolbox_rf2o.sh
./ekf/start_ekf.sh
./nav2_1028/start_chassis.sh        # 要遙控才需要

# 存檔：pgm/yaml + posegraph
ros2 run nav2_map_server map_saver_cli -f .../maps/<name>
ros2 service call /slam_toolbox/serialize_map \
  slam_toolbox/srv/SerializePoseGraph "{filename: '.../maps/<name>'}"

6.2 日常：slam_toolbox localization

SLAM_MODE=localization \
SLAM_PARAMS=/nvt_ros2_example/slam_toolbox_rf2o/slam_toolbox_localization.yaml \
/nvt_ros2_example/slam_toolbox_rf2o/start_slam_toolbox_rf2o.sh

# 或一次起完整 stack（SLAM localization + EKF + Nav2 + driver）
/nvt_ros2_example/slam_toolbox_rf2o/start_all_localization.sh

6.3 日常：AMCL

MAP_FILE=/nvt_ros2_example/slam_toolbox_rf2o/maps/slam_map_latest.yaml \
  /nvt_ros2_example/slam_toolbox_rf2o/start_all_amcl.sh

6.4 重新給初始位置（兩者通用）

# RViz: 2D Pose Estimate（Fixed Frame 要設 map）
# 或指令列：
python3 /nvt_ros2_example/slam_toolbox_rf2o/nav2_1028/tools/set_initial_pose.py X Y YAW_DEG

7. 注意事項

posegraph 一定要先存

map_saver_cli 只會產生 .pgm/.yaml；localization 模式需要 serialize_map 產生的 .posegraph/.data。

WebUI 的「Save map」已加入 posegraph 儲存（僅 mapping 模式會成功）。

初始姿勢要對

localization：map_start_pose: [x, y, yaw] 或 /initialpose。

AMCL：amcl.initial_pose 或 /initialpose。

給錯太遠 → 兩者都會收斂失敗。

localization 不會建圖

它只對既有 posegraph 定位，/map 固定不變。場地變動要靠 costmap 的 obstacle layer，或重新建圖。

AMCL 的 transform_tolerance

AMCL 的 map→odom 時戳 = scan + transform_tolerance（目前 1.0 s），所以年齡會看到 −0.9 s，這是設計，不是延遲。
