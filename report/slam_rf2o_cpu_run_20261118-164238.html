跟隨 53.4%（p95 65.5%），是這幾筆裡最低的。 比 RTAB-Map + ICP（15:45）的 72.2% / 82.5% 少約 19 個百分點，差距幾乎全部來自 odom 節點（rf2o 1.7% vs ICP 13.4%）。
  • rf2o 整段 1.7%、跟隨期間 1.6%，odom 本身幾乎不吃資源；與 11-13 兩筆完全一致。
  • slam_toolbox 這次 8.9%（max 35.3%），約為 11-13（2.8~3.7%）的 2.5 倍 → 動態建新圖比載入既有圖/定位重。
  • 回程後（約 68.9 s）slam_toolbox 單筆 37.1%、總 CPU 89%，屬 loop closure / 地圖整理，與跟隨負載無關。
  • 整段 max 96.5% 在 4.2 s（bag discovery + 相機初始化），跟隨期間最高 69.1%。

7. 建議

  • 相機（11.0%）+ AI（6.6%）現在是最大塊；AI 關閉時只留 gyro/accel 可省掉大部分。
  • slam_toolbox 在回程的 37% 尖峰若出現在跟隨中，會拖慢 map→odom；可觀察是否與 loop closure 同步。
  • rf2o 便宜但只做相鄰掃描匹配，長距離會累積漂移；若地圖出現重影，這是預期中的取捨（ICP 較穩但貴 7 倍）。
  • 要更乾淨的基準，可用 BAG=0 再跑一次，扣掉量測本身約 8%。
