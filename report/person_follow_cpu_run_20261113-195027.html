8. 結論

跟隨期間 CPU 健康：mean 53.5%、p95 65.4%、max 65.4%。 四核每顆核心都低於 72%，沒有跟隨中飽和。
  • 整段 p95 94.1% / max 94.8% 來自 0~10 s 啟動：bag discovery（單核 59%）＋相機（單核最高 57.5%）。
  • AI 與相機仍是最大固定成本：跟隨期間合計四核約 23.9%。
  • SLAM 跟隨平均四核 3.6%，但 +26.6 s 出現單核 68%（四核 17.0%）尖峰，只持續一個取樣。
  • monitor 本身約四核 9.4%：follow_watch 6.2%、bag 2.3%、cpu monitor 0.8%。
  • person ID 1 13.74 Hz（bag /person_infos 13.5 Hz），比上一筆 14.25 Hz 低約 0.5 Hz；5 秒區間大多 13.8~15.8 Hz，35~40 s 降到 12.2 Hz。
  • 視覺置中 11 次、timeout 3 次；recovery 0 次，ID 2 只短暫出現 5 筆。

9. 建議

  • 若要降 CPU，先動相機：640×480 @ 15 → 424×240 @ 15，RealSense 可從四核約 11.5% 降到 5~6%。
  • follow_watch 的 6.2%（四核）已經比 bag 還高，若不需要 10 Hz 全量 CSV，可把 summary 週期拉長或減少寫入欄位。
  • 關掉未使用的 Nav2 node：docking_server、route_server、smoother_server、waypoint_follower、keepout_container。
  • SLAM 尖峰只出現在 +26.6 s 一個取樣，暫不處理；若跟隨中持續 >20%（四核）再查 scan match / loop closure。
  • 視覺置中 timeout 3 次，可把 visual_rotation_timeout_sec 調到 4~5 秒再測。
