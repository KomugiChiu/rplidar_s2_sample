6. 觀察與建議

  • 建圖成本集中在 slam_toolbox。整段 7.5%、max 33.7%（+85.4 s）；後段 +85.4 s 的總 CPU 68.9% 與 slam_toolbox 33.7% 同步，較可能是 map update / loop closure（do_loop_closing: true、map_update_interval: 5.0）。若地圖品質正常，這是預期行為；若同時出現 scan drop 或 map→odom 延遲，再調 loop_match_* / map_update_interval。
  • rf2o 很便宜。1.6%（max 2.8%）；與 17:07（1.7%）、16:42（1.7%）一致，odom 不是建圖瓶頸。
  • camera 是第二大固定成本（6.5%）。它是 EKF 的 RealSense；若建圖不需要視覺/IMU，關掉可省下大部分，但 EKF 的 odom 融合也會受影響。
  • 量測負擔約 7.1%。python3（bag / follow_watch / monitor）4.3% + ros2 launch 2.5%；要更乾淨的基準可用 --no-bag --no-watch 再跑一次。
  • 啟動尖峰與建圖無關。整段 max 78.3% 在 +2.1 s（bag/monitor/DDS discovery）；建圖主段 p95 只有 42.2%。
  • scan drop 集中在啟動。/tmp/slam_toolbox_only/logs/slam.log 共 9 次 Message Filter dropping，大多在 17:25:56~17:26:12（啟動/前段），後段 map update 尖峰期間沒有再出現。
  • 地圖尚未存檔。/nvt_ros2_example/maps 最新仍是 11-18 的 slam_map_20261118-0959.*；本次只建圖、沒有新的 .posegraph / .pgm。要保留這次地圖，請跑 record_map.sh / save_map.sh（或 slam_toolbox 的 map_saver）。
