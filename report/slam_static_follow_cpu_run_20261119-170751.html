6. 觀察與建議

  • slam_toolbox 是 static follow 最值得觀察的節點。整段 6.5%、跟隨 8.3%、max 25.3%（+53.1 s）；單筆 raw CPU 106%（單核），node 有 28 個 thread。啟動 log 顯示 options.num_threads: 50 exceeds maximum ... 4；這是 slam_toolbox Ceres solver plugin 內建的 options_.num_threads = 50（solvers/ceres_solver.cpp），不是 yaml 參數，Jazzy 的 Ceres 會 bound 到 4。若尖峰造成 map→odom 延遲，需改 source 或換 solver plugin；先確認 +53.1 s 的尖峰是否與 scan matching / 地圖大小有關。
  • rf2o 不是瓶頸。整段 1.7%、跟隨 1.6%；與 16:42（1.7%）、16:51（1.8%）一致。
  • 相機 + AI 是最大塊（17.6%）。camera 10.8% + AI 6.8%；若不需要 AI，關掉可省下大部分。
  • 量測負擔約 10.3%。python3（bag / follow_watch / monitor）6.8% + ros2 launch 3.1%；要更乾淨的基準可用 --no-bag --no-watch 再跑一次。
  • 啟動尖峰與跟隨無關。整段 max 93.8% 在 +7.2 s；跟隨期間最高 76.4%（+53.1 s），返回段最高 65.5%。
  • static 的取捨。總 CPU 比動態建圖低 5.2 個百分點，但跟隨期間 slam_toolbox 仍要 8.3%；static 省掉的是地圖成長 / loop closure，不是 scan matching。
